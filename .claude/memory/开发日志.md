## 2026-06-24 会话修正记录

### Hero 区表述
- ❌ "数据分析学习者" → ✅ "数据分析者"（不是在学习，是有能力的）
- ❌ "机器学习开发" → ✅ "AI工具使用者"（更准确，不是做 ML 开发的）
- ❌ 英文词 "actionable" → ✅ 中文自然表达

### 项目定位措辞
- 绝区零 2.7 X平台 ≠ "一次性快照" → 是「决策报告」，为运营投放决策提供数据支撑
- 绝区零 YouTube 项目 = 「长期大盘追踪」，而非一次性监测

### 项目链路描述
- 不能笼统写"数据爬取→分析"，必须体现完整流程
- YouTube 项目正确链路：自研爬取 + 官方 API 补爬 → 自研工具判定地区/游戏 → 固定工作流分析 → 简报输出

### 文案风格偏好
- 不要中英混杂（"actionable"→中文）
- 要自然口语化，不要翻译腔
- 技术名词可以保留英文（FastText、YouTube 等）

### 版本管理
- **硬性规则**：每次修改 `index.html` 或 `style.css` 前，必须先将当前版本备份到 `历史版本/日期_vN_描述/`
- 无例外：即使只改一行字、改措辞，也必须备份后再改
- `历史版本/README.md` 记录每个版本的日期、内容和触发来源
- 如果不确定当前版本是否已备份，先检查再动手

### 迭代流程（必须遵守）
1. 用户提出需求 → 先写生成方案N.txt
2. 用户确认方案后 → 才动手改代码
3. 改之前备份当前版本到历史版本
4. 改完后更新开发日志、README 和项目基本信息
- 禁止跳过方案步骤直接修改
